# 分层验证与验收记录

验收分为主机数值验证、板端单模块验证、完整实时链路和作品展示。每一层保留真实命令与结果，再进入下一层。v0.1 的CPU参考程序可以先验证，Qt编译与运行以实际CI或本机结果为准，真实RPE插件和板端30分钟测试目前仍需目标硬件执行。

不要把主机CPU速度、合成系数听感或普通主机上的DSP-wrapper单测记为DM8168的DSP性能结果。

## 主机自动验证

在项目根目录、具备C编译器和Python 3.8或更新版本的主机执行：

```sh
python3 tools/build.py --test
python3 -m unittest discover -s tests -p 'test_*.py'
python3 tools/demo.py
```

如需使用特定编译器，按主入口说明提供 `--cc`、`CC` 或 `--zig`。内存/未定义行为检查可在支持的编译器与宿主上另执行 `python3 tools/build.py --test --sanitize`，不将原始SDK工具链是否支持sanitizer作为板端功能要求。

自动测试重点覆盖静音、已知脉冲、正负满幅及饱和、左右输入的向零平均、一次性与分块处理一致、历史保持、旁路、方向交叉淡化与连续控制请求。素材工具还需验证PCM帧完整性、WAV格式、采样率拒绝、显式HRIR重采样、长度上限和系数顺序。

生成的演示文件使用原创低幅测试音与显式标记的合成系数。检查输出帧数与输入一致、静音输出为零、方向A/B结果存在预期差异，并确认结果摘要没有将其描述为实测HRIR或硬件DSP。

### 独立参考比较

使用 `tools/reference.py` 的全信号卷积与后端流式输出对比。参考实现直接索引完整输入，使用Python任意精度整数，与C核心的环形缓冲区实现相互独立。以下示例比较固定方向，不包含切换：

```sh
python3 tools/reference.py --input results/demo/input.pcm --bank results/demo/synthetic.hrir --direction 0 --output results/demo/reference-a.pcm
```

将参考输出与演示目录中的方向A PCM逐字节比较。两者均不自动追加卷积尾部，不能把长度相同视为完整尾音已经输出。切换测试另外核对淡化端点、持续历史和重复请求行为。

## 板端分段验证

| 阶段 | 方法 | 通过条件 |
| --- | --- | --- |
| 系统与交叉编译 | 运行已知Hello World，再运行本项目CPU离线程序 | ABI和运行库匹配，输入输出帧数正确，日志可复现 |
| ALSA直通 | 独立录音保存PCM，再独立播放 | 明确设备与实际格式，48000 Hz/S16_LE/双声道协商成功 |
| 音频FIFO | 使用文件来源和直通消费者逐段加入FIFO | 无字节丢失、声道错位或截断；每条FIFO只有一个消费者 |
| 原始RPE | 跑通本地课程copy，再运行简单已知计算 | 确认确实调用DSP，缓冲区、缓存和返回数据正确 |
| DSP算法 | 先已知脉冲/低通FIR，再连续HRIR | CPU与RPE在约定数值标准内一致，跨块历史不断裂 |
| Qt客户端 | 无后端、连接后端、重启后端 | 无后端空波形，状态真实，命令有效，断线与重连正确 |
| 完整链路 | 录音→FIFO→CPU/RPE→FIFO→播放 | 音频持续，界面不在音频主链路中 |

先使用文件与CPU验证软件边界，RPE出错时退回copy测试隔离通信与算法问题，Qt问题不应阻塞离线数值验证。课程录放示例的44100 Hz与当前48000 Hz约定需明确统一。

## 控制与故障场景

- 方向A/B切换和旁路切换使用相同输入，对照无切换基线，确认淡化保留旧端点和新端点、不清空历史；听感仅作补充，不以“听不出爆音”替代数值检查。
- `STOP` 后输出应为静音，但累计帧数继续增长，`START` 恢复；退出启动脚本后才检查ALSA设备是否已释放。
- 关闭Qt或暂停其读取，音频后端应继续运行，允许 `visual_drops` 增长；它不是ALSA欠载计数。
- 停止后端后，Qt约1.5秒后清空过期指标与波形并禁用控制；后台恢复或重建FIFO后，无需重启Qt应可恢复显示。
- 输入少于一整块但仍包含完整立体声帧时正确输出短块；输入结束在半个立体声帧内时明确报错。
- 输入采样率与系数不符、系数数量不符、非法模式和缺失RPE插件时明确失败；选择RPE不得静默回退CPU。
- 高频连续方向请求不会创建无限队列；当前淡化先完成，后续仅执行最后待处理目标。

## 处理耗时与30分钟实时验收

在相同板卡、采样率、素材、系数长度、优化级别和切换计划下分别记录CPU与RPE结果。默认1024帧、48000 Hz的完整块预算为约21333.333微秒，末块按实际帧数计算预算。

`--stats` CSV 的 `process_us` 是宿主围绕一次后端处理的计时：CPU为CPU处理耗时，RPE为同步插件往返耗时。它不包含采集和播放设备缓冲、全部I/O等待或声学传输，不能在报告中改称纯DSP计算时间或端到端延迟。无CPU/RPE同条件实测时，不给出加速比。

汇总真实CSV的块数、总帧数、平均、p95、p99、最大处理时间和 `deadline_miss` 总数。计算百分位时应在报告中注明采用的排序/插值方法，保留原始CSV便于复核。静音和方向切换块也纳入统计，因为切换期间可能同时计算新旧滤波器。

最终在板上运行至少30分钟的真实采集与播放，启动脚本使用 `--duration 1800`。测试期间操作方向、旁路和静音，并关闭/恢复Qt。目标是后端无崩溃、处理超时为零、ALSA日志无欠载/溢出、退出后设备与子进程均可正常回收；若未达到，记录实际失败次数和定位结果，不把目标写成已测事实。

ALSA欠载/溢出必须从 `arecord`、`aplay` 的stderr及必要的设备状态独立核对。`deadline_misses=0` 只能说明受测后端处理没有超过块预算，不能证明完整链路没有音频卡顿。端到端延迟需要已知脉冲、回环录音或相应仪器另测。
