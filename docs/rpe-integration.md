# 从课程 RPE 示例接入真实 DSP

v0.1 未包含可直接加载的 TI RPE 插件。仓库中的 DSP wrapper 是算法边界，不是完整 xDM 插件，也不包含课程原始固件、RPE源码、HRIR头文件或老师提供的音频。以下步骤供持有本地课程 SDK 与示例的开发者完成实际适配。

真实插件必须在目标板 Linux 进程中调用本地 RPE 运行库，将数据送到实际 DSP，并在同步调用返回后提供本块输出。不能在名为 RPE 的插件内部改为调用 ARM CPU 核心，却向界面报告 DSP 后端。

## 1 准备与验证本地课程资料

确认课程 SDK 中实际存在并能构建以下组件：

```text
ti-ezsdk_dm816x-evm_5_05_01_04/
  component-sources/rpe_1_00_00_12/
    tests/copycodec/
    tests/testcases/test1/
```

以实际安装版本为准，不混用不同版本的 RPE、SysLink、IPC、SysBIOS、XDC及编译器。课程原始 tests、sqrt/FFT示例、分块卷积代码与HRIR头文件需要从课程提供的资料中取得；它们不嵌在本仓库接口头文件中。

先备份已能运行的本地原始示例，并单独完成 copy 的编译、安装与目标板运行。随后可用已知输入的 sqrt或FFT验证参数、共享缓冲区和返回数据。保存实际命令和日志，再开始空间音频修改。

课程HRIR示例出现两组左右耳头文件：`L40e045a_header.h`、`R40e045a_header.h`、`L_40e161a_header.h`、`R_40e161a_header.h`。必须取得原始数据的采样率、时间顺序、方位定义、缩放和许可说明，不能从文件名猜测这些信息，也不能据此假定允许公开再分发。

## 2 宿主插件 ABI

插件是 ARM Linux 的共享库，须与 `spatial-audio` 使用兼容的 ARM EABI、运行库和项目头文件。它导出符号 `spatial_rpe_get_api`，返回指向稳定函数表的指针；若实现文件使用 C++，该导出入口使用 C linkage，避免符号改名。

当前 `SPATIAL_RPE_PLUGIN_ABI` 为1，函数表定义在 `include/spatial_rpe_plugin.h`：

| 入口 | 责任 |
| --- | --- |
| `open(bank, fade_frames, mode, error, error_size)` | 创建会话、加载或连接实际DSP算法、分配共享缓冲区并设置初始系数与模式；成功返回会话指针，失败返回NULL并清理部分资源 |
| `set_mode(session, mode, error, error_size)` | 将方向/旁路请求传给实际算法，返回0表示成功，非0表示失败 |
| `process(session, input, output, frames, error, error_size)` | 同步处理当前块，成功时返回0并填满 `frames` 对应的双声道输出 |
| `close(session)` | 释放本会话的共享内存、RPE对象和相关句柄 |

输入输出都是宿主进程内的 `int16_t` 双声道交织数组；`frames` 是立体声帧数，不是字节数，当前命令行后端每次最多1024帧。完整块的输入和输出各4096字节。末块可以更短，插件必须只推进有效帧数的DSP历史并返回对应输出，不能把补齐的静音帧当成下一次调用前真实消耗的输入。

`bank` 在后端会话存活期间保持有效且不变。插件可在初始化时向DSP复制、转换该系数库，但不能将宿主地址当DSP地址使用。`error` 为调用方提供的有界错误缓冲区，失败时写入可读原因且不能越界。

该ABI是同一ARM进程内的函数调用约定，不是跨核报文；`spatial_bank`、`spatial_processor`、`size_t`、指针和函数表都不允许直接视为ARM/DSP共享线格式。动态加载失败不会回退CPU。

## 3 绑定课程 RPE 生命周期

从已经跑通的 `test1` 提取对象初始化、算法创建、缓冲区查询、共享内存申请、控制调用、处理调用和销毁流程，封装进插件的对应生命周期。具体 TI 类型、函数签名、结构大小、命令ID及链接选项必须直接依据本地 SDK 头文件与原始例程，不复制其他SDK版本的假定ABI。

课程示例通过控制调用查询输入输出缓冲区大小，ARM端再使用 `Memory_alloc` 申请共享区，示例采用128字节对齐。适配时沿用本地已经验证的共享区ID、对齐与地址转换机制，并确认申请大小满足当前固定块、有效长度和算法参数的要求。

输入写入共享内存后、DSP访问前，以及DSP写完后、ARM读取前，按本地框架要求执行缓存写回/失效和所有权转换。某些RPE封装已经处理部分缓存操作，应根据原始示例确认责任归属，不能凭“共享内存”推断双核缓存自动一致，也不能盲目重复缓存操作。

`process` 的耗时会包含在宿主 `--stats` 计时中，因此共享缓冲区复制、缓存维护、同步IPC与算法处理属于这段调用的测量范围。若另外测纯DSP算法时间，应使用独立的DSP计时并明确测量边界。

## 4 绑定 DSP 算法 wrapper

`rpe/spatial_dsp.h` 与 `.c` 提供以下逻辑入口：

- `spatial_dsp_init`：绑定系数库并初始化连续处理状态。
- `spatial_dsp_configure`：校验版本、方向、旁路和历史复位请求，再更新处理模式。
- `spatial_dsp_process`：使用实际有效帧数完成当前块的双耳渲染。

把它们接入本地xDM算法的初始化、控制和处理函数，并按SDK要求完成函数表、算法注册、内存记录、DSP链接与固件生成。wrapper没有提供这些TI专用部分。在普通主机运行 `test-dsp` 只验证wrapper的数值和控制行为。

`spatial_dsp_control` 中使用固定宽度32位字段，版本为1；绑定层逐项复制和校验，不把宿主结构强制转换为共享结构。`reset_history` 只用于明确的新会话或复位操作，正常换方向、旁路和跨块处理保持历史。

不要用16位 `frameType` 承载持续增长的块号。有效帧数、参数版本与返回状态应使用本地SDK允许的明确参数机制，并在适配层验证范围。需要额外计数时使用足够宽的独立字段；`extendedError` 保留错误含义，不能借其高低16位回传普通波形、方向或时间戳。

## 5 HRIR 与数值一致性

首版使用连续时域FIR，不依赖FFT分区卷积。核心系数为Q15，因果顺序，512抽头是默认值而非硬编码上限，最多支持1024抽头。原课程示例若使用不同系数排列或缩放，需要显式转换并以脉冲验证，不能仅把头文件名改成项目格式。

本项目统一48000 Hz。44100 Hz、512抽头的HRIR需要显式离线重采样，按当前转换工具的向上取整规则通常成为558抽头，保留时间长度，不能强行截回512。实际长度与任何量化饱和以生成的元数据为准。

`tools/audio_tools.py import-hrir` 目前接受四份单声道16位PCM WAV，顺序为 A-left、A-right、B-left、B-right；若手头只有C数组，应先确认数值语义并在本地完成受控转换。导入时记录来源、许可和方向定义，采样率不匹配时需显式 `--resample`，工具不会静默转换或截断超过上限的尾部。

项目文本系数库的头部示例为：

```text
SPATIAL_HRIR_V1 48000 512 synthetic=1
```

后续按 A-left、A-right、B-left、B-right 排列四组Q15整数。`synthetic=1` 仅表示教学合成系数，不可标成真实HRIR；导入数据为 `synthetic=0`，仍需人工确认其实际来源和空间定位适用性。

## 6 插件接入验收

先对同一个PCM、同一系数库和同一控制序列进行CPU与RPE离线对比，通过静音、脉冲、饱和、短块、跨块历史和方向切换测试，再连接ALSA和Qt。使用本项目相同定点算法时输出应逐样本相同；若改用优化库而引入舍入差异，须先定义并说明误差标准。

完成真实共享库后才执行：

```sh
./spatial-audio --backend rpe --rpe-plugin ./libspatial_rpe_course.so --bank measured.hrir --input input.pcm --output rpe-output.pcm --stats rpe.csv
```

上述库名是待实现插件的示例名称，仓库不提供该二进制文件。验收需保存真实DSP固件标识、插件构建参数、SDK版本、板端运行日志和对比结果，之后才能将项目状态标记为RPE硬件已接入。
