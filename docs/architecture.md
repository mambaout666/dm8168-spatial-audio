# 系统架构与实现边界

本项目面向 DM8168 的音频、异构处理和 Qt 课程实践，将一个单声源渲染为双耳输出，并提供两组方向系数的平滑切换。v0.1 提供可在主机运行的 CPU 参考实现、数值测试、独立 Qt 客户端源码，以及接入课程 RPE 示例所需的接口边界。真实 RPE 插件、板上音频链路和 Qt 显示仍需在目标环境验证。

默认系数是带明确标记的合成延时/增益测试库，用于验证接口与数值行为。它不是真实 HRIR，不能作为空间听感或 DSP 加速效果的证明。导入真实 HRIR 后仍需确认数据来源、采样率、方向定义和许可。

## 数据流

```text
文件 / ALSA arecord
        |
        v
独占音频输入 FIFO
        |
        v
ARM 后端 ---- CPU reference
        |           或
        +------ 本地 RPE 插件 ---- 共享缓冲区 / RPE ---- DSP FIR
        |
        v
独占音频输出 FIFO ---- ALSA aplay / 文件

Qt 客户端 ---- control.fifo ---- ARM 后端
Qt 客户端 <--- telemetry.fifo -- ARM 后端
```

音频处理与界面属于不同进程。每条音频 FIFO 只有一个消费者，Qt 不与 RPE 后端共读音频 FIFO。命名管道的多个读者会分走字节，不能用来广播同一份音频。

Qt 只读取低频遥测和抽样波形，后端以非阻塞方式发布，界面未启动或读取变慢时允许丢弃可视化数据。可视化丢弃数量与音频丢帧是不同指标，不能相互替代。

## 音频与算法约定

| 项目 | v0.1 约定 |
| --- | --- |
| 音频流 | 48000 Hz，S16_LE，双声道交织，顺序为 L、R、L、R |
| 数据块 | 最多1024立体声帧，即4096字节；1024帧对应约21.333 ms |
| 输入声源 | 使用较宽整数求 `(L + R) / 2`，向零取整，得到一个单声源 |
| 输出 | 同一单声源分别与当前方向的左耳、右耳系数卷积 |
| FIR | 连续时域 FIR，Q15 系数，64位累加，半值远离零舍入并饱和为 int16 |
| 系数顺序 | 因果顺序；`h[0]` 乘当前输入，`h[1]` 乘前一个输入，不隐式逆序 |
| 系数长度 | 默认512抽头，支持1至1024抽头；四组系数统一长度 |
| 方向 | A、B 两组索引，不凭文件名推断角度 |
| 方向与旁路切换 | 默认1024帧线性交叉淡化，包含首尾端点 |
| 旁路 | 复制单声源到左右耳，不保留原立体声声像 |

本项目将输入立体声下混为一个声源后再渲染，不实现两个独立声源的定位。反相立体声输入可能在下混时相消，验证音效时应使用明确的单声源素材或双单声道输入。

处理器持续保存 FIR 历史，跨块、旁路和方向切换均不清空。淡化过程中再次请求新模式时，先完成当前淡化，再执行最后一个待处理请求，避免在一次淡化中途突然更换端点。

文件结束可以是不满1024帧的完整立体声块，输出长度与输入相同。v0.1 不自动追加 FIR 尾音；需要完整卷积尾部时，应在输入末尾显式追加 `taps - 1` 帧零值。输入若结束在半个立体声帧内则报错。

原始 PCM 不带采样率或 WAV 头。不能把 MP3 压缩字节或完整 WAV 文件直接当 PCM 交给后端，素材准备由 `tools/audio_tools.py` 完成。

## CPU 与 RPE 的分工

CPU 后端直接调用可移植核心，可作为独立数值基准。选择 `--backend rpe` 时，程序必须加载明确提供的本地共享库；插件缺失、ABI 不匹配或初始化失败会终止运行，不回退为 CPU 冒充 DSP。

`include/spatial_rpe_plugin.h` 定义 ARM Linux 进程内的插件 ABI，当前版本为1，入口为 `spatial_rpe_get_api`。它不是 ARM 到 DSP 的线格式，不能将含指针、`size_t` 或函数指针的宿主结构原样传到 DSP。

`rpe/spatial_dsp.c` 仅封装了可移植算法的初始化、模式配置和处理入口，供后续本地 TI 适配使用。它没有实现完整的 xDM 算法注册、RPE 对象创建、DSP 固件链接或目标板加载流程。在主机编译和测试此文件不代表已经在 DSP 上执行。

真实插件的适配顺序、缓冲区所有权与缓存要求见 [RPE 集成步骤](rpe-integration.md)。

## 控制与遥测

Qt默认连接 `/tmp/dm8168-spatial-audio`；后端通过 `--runtime-dir` 显式启用控制与遥测，并创建 `control.fifo` 和 `telemetry.fifo`。启动脚本默认创建唯一的临时运行目录并打印给Qt，也支持指定目录。目录应由会话用户拥有且不可被其他用户任意写入，Qt与后端使用同一个目录和同一会话用户。

控制命令为换行结束的文本：`START`、`STOP`、`DIRECTION 0`、`DIRECTION 1`、`BYPASS 0`、`BYPASS 1`。方向和旁路在后续处理块边界生效。`STOP` 将输出静音但继续处理和保存历史，`START` 恢复输出；真正结束会话、释放 ALSA 设备由会话启动脚本负责。

遥测包括64位累计块数/帧数、模式、块处理耗时、处理超时计数、可视化丢弃数量，以及 `backend` 和 `synthetic`。`synthetic` 描述系数库而非音频源，`backend=cpu` 不表示 DSP。波形只是输入单声源和左右输出各16个采样点的预览。

Qt 每100 ms轮询，超1.5秒无有效状态后清空过期显示并禁用控制，后端恢复后重连。完整行协议、Qt4/Qt5构建和显示环境区别见 [Qt 客户端说明](../qt/README.md)。

## 时间指标的边界

`--stats` 记录围绕 `backend_process` 的宿主计时。CPU 模式覆盖当前块的下混、FIR和淡化计算；RPE 模式覆盖插件同步处理调用，因此可以包含共享缓冲区复制、缓存操作、IPC和DSP运算。

这不是纯 DSP 核计算时间，也不包含完整的采集、FIFO等待、播放设备缓冲或声学延迟。处理时间超出当前块的帧数预算时计入 `deadline_misses`，但该计数不能证明 ALSA 没有欠载；实时稳定性需另外结合 ALSA 日志与端到端测量确认。
